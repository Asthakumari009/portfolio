Case study

Norn, from problem to published package.

// The problem

Every session with an AI coding agent starts from zero. It forgets your stack, your decisions, and your conventions, so you re-explain the same project every day. Naive memory tools make it worse: they store contradictory facts and silently rot.

// What I did

Built Norn, a persistent-memory MCP server in TypeScript. Every new memory passes a two-stage conflict gate: an embedding-similarity check, then an NLI model that separates contradictions from updates. Conflicts land in a review UI instead of overwriting silently, and a live dashboard streams the whole agent fleet over SSE onto a real-time orbital map.

// The result

Published to npm as @samad001z/norn-server and @samad001z/norn-core, with 89/89 tests passing. One command installs it into any MCP client, Claude Code and Cursor included, and the agent's memory survives across sessions.
